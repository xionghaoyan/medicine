# dudu 医学系统

一个基于 **React + Vite + FastAPI + SQLite** 的门诊 HIS 教学项目。已包含患者建档、门诊挂号、接诊开方、线下收费、药房发药、批次库存、统计与审计。数据均为虚构演示资料。

所有代码、文档、运行数据与界面素材位于本目录。前端是 `medicinefronted`，后端是 `medicinebackend`；与上一级旧项目使用不同端口、数据库、随机密钥和会话 cookie。

## 开发入口

后续开发先读 [HIS 开发文档](docs/HIS开发文档.md)，再读 [前端规范](medicinefronted/AGENTS.md) 或 [后端规范](medicinebackend/AGENTS.md)。文档已定义功能范围、视觉、目录、接口、表结构、权限、金额、事务、数据迁移与验收规则；业务或接口变化必须先更新文档。

## 一键启动

需要 Python **3.11+**、Node.js **20.19+ / 22.12+** 与 npm。在 `dudu医学系统` 目录执行：

```bash
./start.sh
```

脚本检查依赖，必要时创建后端 `.venv`、安装 Python 和 npm 依赖，再启动前后端。保留终端运行，按 Ctrl+C 结束这次启动的进程。

| 入口 | 地址 |
|---|---|
| 前端页面 | http://127.0.0.1:5178 |
| API 交互文档 | http://127.0.0.1:8008/docs |
| 健康检查 | http://127.0.0.1:8008/api/v1/health |

日志保存在 `.local/logs/`。端口已占用会明确报错，不会停止其他应用。启动脚本不重置数据库。

也可以用两个终端单独启动：

```bash
cd medicinebackend
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8008 --reload
```

```bash
cd medicinefronted
npm run dev
```

如果系统中的 Python 不满足要求，可以使用 `PYTHON_BIN=/实际路径/python3.12 ./start.sh`。手动安装为 `python3.12 -m venv .venv`、`.venv/bin/python -m pip install -r requirements.txt`（在后端目录），以及 `npm ci`（在前端目录）。

## 走通一次门诊

1. 管理员或收费员进入“患者档案”，点击“新建患者”完成建档。
2. 点击患者行的“挂号”，选择日期、医生和上下午时段，确认后获得挂号凭证。
3. 医生进入“医生工作站”，选择候诊患者并“开始接诊”，填写主诉、诊断、药品、数量、用量与频次，然后开具处方。演示医生账号对应林知远。
4. 收费员进入“收费结算”，核对明细、选择线下收款方式，勾选核对项后确认收款。
5. 药师进入“药房发药”，核对患者、药品数量和批次效期，再勾选核对项并确认发药。
6. 管理员进入“运营管理 → 操作日志”，按处方编号检索整个流程；统计报表可按日期查询和导出 CSV。

管理员也可演示完整闭环；四个角色的权限仍由后端强制验证。

## 功能与设计

- **工作台**：实时指标、7 日就诊趋势、科室分布、候诊记录、快捷入口和待办。
- **门诊服务**：患者检索与历史、过敏信息、挂号和退号、号源排班、医生接诊、处方查看/作废/打印、收费和退费。
- **药房中心**：发药核对、批次与效期、低库存提示、新药建档、价格维护、单笔入库、CSV 模板及逐行导入反馈。
- **运营管理**：真实业务报表、CSV 导出、可检索审计、机构信息、账户创建、角色调整与启停。
- **通用交互**：全局搜索、帮助、待办提醒、加载/错误/空状态、键盘弹窗、响应式导航。

dudu 使用钴蓝和墨蓝、顶部导航与横向业务页签。登录页、品牌和数据工作台独立设计；首页采用不对称数据布局与待办列，不沿用旧项目的深绿宽侧栏。

## 业务规则

- 金额在数据库和 API 中使用整数分；后端按药品档案计算，并保存处方单价快照，前端不能传入自定价格或总额。
- 挂号占号、队列编号和审计同事务，余量为 0 才拒绝；最后一个号源只能被一个请求成功占用。未开方可退号，退号释放号源但不复用队列编号。
- 收费预留有效批次库存，实际库存暂不减少；发药才扣减实物库存并释放预留。重复收费或发药不会重复扣账或扣库。
- 未发药处方可退费并释放预留；已发药的处方在本版本不能直接退费。多药处方只要一项不足，收费事务整体回滚。
- 批次按效期优先预留，过期和停用药品会被拦截。已有批次或处方的药品不允许修改规格、单位。
- 收入按实际处方收款日计入、退费日冲减。挂号显示的诊查标准仅作参考，本版本不收取挂号费、不计入收入。
- CSV 相同药品编码和批号去重，合法行独立提交，错误行返回行号；药师不能借助导入修改价格或创建新药。
- 登录使用 bcrypt 哈希、HttpOnly cookie 和服务端会话；医生仅访问本人诊疗数据。退出和禁用账户会撤销会话。

## 数据与配置

可复制两个目录中的 `.env.example` 为 `.env` 再调整。数据库和密钥首次启动时只在本项目后端的 `data/` 创建；不要复制上一级旧项目的数据库或密钥。

| 配置 | 默认值与用途 |
|---|---|
| `DATABASE_PATH` | `data/dudu.sqlite3`，相对后端目录 |
| `SEED_DEMO` | `true`，只在新空库初始化虚构数据 |
| `DEMO_PASSWORD` | `DuduDemo2026!`，只影响首次创建的演示账户 |
| `JWT_SECRET` | 留空自动创建 `data/.jwt_secret`；自定义需至少 32 字符 |
| `SESSION_HOURS` | `8` |
| `COOKIE_SECURE` | 本地 HTTP 为 `false` |
| `CORS_ORIGINS` | 本地 localhost / 127.0.0.1 的 5178 端口 |
| `VITE_API_PROXY_TARGET` | `http://127.0.0.1:8008` |
| `VITE_API_BASE` | `/api/v1` |

会话 cookie 为 `dudu_his_session`，避免与旧项目串用。手动调用写接口需要登录 cookie 和 `X-Requested-With: his-web`。

迁移文件在 `medicinebackend/app/migrations`，执行前通过 SQLite backup API 生成一致性备份。禁止删库重建；恢复流程见开发文档 §5。`.gitignore` 已排除数据库、密钥、`.env`、虚拟环境、node_modules、构建缓存、日志和临时测试文件。

`SEED_DEMO=false` 不创建演示账户；首次本地体验请保留默认值。修改 `DEMO_PASSWORD` 不会重置已有密码，登录页快捷按钮仍填入上述默认演示密码。

## 当前范围

本项目是本地、单机构、门诊教学系统。线下收款和退费仅记录演示结果，不连接真实支付；诊断和处方由医生录入。医保联网、住院、LIS/PACS、电子签章及模型服务不在本次范围内。
